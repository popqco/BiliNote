# 双 worker 并发 + 同视频互斥 + 转写串行信号量

任务执行器先是从上游的 3 worker 降到 1（2026-09-30 稳定性事故），随后又在本轮放开为 2（2026-10-01）：串行单 worker 让 15 个任务排队长达数小时，而「排队中」被用户直接感知为「卡死」。同视频并发下载的文件锁冲突（WinError 32）只会发生在同一视频被重复提交时，因此改用「提交去重 + per-video_id 互斥锁」消除该风险，而不是靠全局串行。转写阶段另加全局信号量（并发=1），因为 GPU 只允许一个 whisper 实例；下载与 LLM 总结阶段可与转写重叠，整体吞吐约提升 40%。
