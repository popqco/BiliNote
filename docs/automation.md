# 自动化：稍后再看定期总结 + 通知

> 需求来源：定期检索 B 站「稍后再看」，为还没有笔记的视频自动生成总结，并把每轮结果汇总推送到微信/邮箱。
> 设计决策见 [ADR-0004](./adr/0004-dual-schedule-with-file-lock.md)。

## 前置条件（必读）

**必须配置 B 站 Cookie（SESSDATA）**——「稍后再看」是账号数据，未登录无法读取。

1. 浏览器登录 bilibili.com；
2. F12 → Application（应用）→ Cookies → `https://www.bilibili.com` → 复制 `SESSDATA` 的值
   （或直接复制整行 Cookie 字符串，格式 `SESSDATA=xxx; bili_jct=yyy; ...` 也支持）；
3. BiliNote →「设置 → 下载配置 → 哔哩哔哩 Cookie」粘贴保存。

Cookie 过期（一般数月）后：自动化会在日志里提示 Cookie 失效并停止，更新 Cookie 即恢复。

## 配置入口

「设置 → 自动化」：

| 配置项 | 说明 |
| --- | --- |
| 启用自动化 | 总开关（默认关） |
| 检查频率 | 默认每 120 分钟；应用启动后会补查一次（距上次检查超过半个周期时） |
| 总结范围 | 「全部未总结」= 稍后再看里所有没有成功笔记的视频；「仅最近新增」= 入单时间在最近 N 天内 |
| 每轮最多新提交 | 默认 5，防止一次把几百个视频灌进队列 |
| 生成配置 | 自动化专用：模型/供应商/风格/质量/视频理解开关，独立于首页表单 |
| 通知渠道 | WxPusher（微信）与 SMTP（邮箱），可各自独立启用 |

去重规则（一轮中每个视频只处理一次）：
- 已有**成功笔记**（数据库 video_tasks 命中）→ 跳过；
- 已有**未完成任务**（排队/生成中）→ 跳过；
- 超出时间窗 / 超出每轮上限 → 跳过（下一轮再处理）。

## 通知推送配置教程（WxPusher / 邮箱）

自动化每跑完一轮发一条汇总，内容形如：

```
【BiliNote 检查轮】10-01 16:43
新增 3：成功 2，失败 1；跳过 2
✅ 系统应用你给我做好了呀！深挖了各家系统才发现……
✅ 计划模式已死
❌ 只学够用的 Linux：长度正好的零基础入门教程：DownloadError: ...
```

两个渠道**互相独立**：可以只开一个，也可以都开；一个发失败不影响另一个，也不影响笔记生成。
配置入口：「设置 → 自动化 → 通知渠道」，填完勾选启用，点**「发送测试通知」**验证。

### 方式一：微信推送（WxPusher，免费，推荐）

WxPusher 是一个免费的消息推送服务：你在它那里建一个「应用」拿到密钥，微信扫码关注它的公众号
拿到自己的 UID，之后程序就能把消息推到你微信里。全程 3 分钟、不需要服务器、不需要备案。

**第 1 步：创建应用，拿 appToken**

1. 打开 <https://wxpusher.zjiecode.com/admin/>；
2. 用**微信扫码登录**（无需注册账号，扫码即登录）；
3. 左侧「**应用管理**」→ 右侧「**创建应用**」；
4. 应用名随便填（如 `BiliNote 笔记提醒`），其他项保持默认，保存；
5. 回到应用列表，点开刚建的应用，复制 **appToken**（形如 `AT_xxxxxxxxxxxxxxxx`）。

**第 2 步：拿你自己的 UID**

1. 在同一个应用详情页里找到二维码（或用微信直接搜索并关注公众号「**WxPusher**」）；
2. 微信扫码关注后，进入公众号 → 底部菜单「**我的**」→「**我的UID**」；
3. 复制那串 UID（形如 `UID_xxxxxxxxxxxxxxxx`）。
   > 想推送给多个人（例如家人共用一台电脑）：让每个人都关注公众号并各自取 UID，
   > 然后把这些 UID 用**英文逗号**连起来填进去即可。

**第 3 步：填进 BiliNote**

| 字段 | 填什么 |
| --- | --- |
| 微信推送（WxPusher） | **勾选**启用 |
| appToken | 第 1 步复制的 `AT_...` |
| UID | 第 2 步复制的 `UID_...`（多个用逗号分隔） |

填完点「**发送测试通知**」，下方会逐条显示结果；微信里几秒内应该收到「BiliNote 测试通知」。

> appToken 相当于密码，别贴到公开仓库或截图里。填错时测试通知会直接显示 WxPusher 返回的原因。

### 方式二：邮箱推送（SMTP）

邮件走的是你**自己邮箱服务商的发信服务器**，所以需要「服务器地址 + 端口 + 账号 + **授权码**」四件套。
授权码不是登录密码——绝大多数邮箱（QQ、163、Gmail）默认禁止第三方程序用登录密码发信，
必须到邮箱网页设置里单独生成一串授权码。

**第 1 步：开服务、拿授权码（以 QQ 邮箱为例）**

1. 电脑浏览器登录 <https://mail.qq.com>；
2. 顶部「**设置**」→「**账号**」（新版为「账号与安全」→「安全设置」）；
3. 找到「**POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务**」；
4. 把「**IMAP/SMTP服务**」打开，按提示用手机发一条短信验证；
5. 验证通过后页面会弹出一串 **16 位授权码**（形如 `abcdwxyzefghijkl`）——只显示一次，先复制下来。

**第 2 步：填进 BiliNote**

| 字段 | QQ 邮箱 | 说明 |
| --- | --- | --- |
| 邮箱（SMTP） | **勾选**启用 | |
| SMTP 服务器 | `smtp.qq.com` | 见下方常见服务商表 |
| 端口 | `465` | 465 = SSL 直连；587 = STARTTLS，两种都支持 |
| 邮箱账号 | `你的QQ号@qq.com` | 完整邮箱地址 |
| SMTP 授权码 | 第 1 步那 16 位 | **不是** QQ 登录密码 |
| 收件人 | `你要收信的邮箱` | 可以就是自己；多个用逗号分隔 |

**常见邮箱服务商对照表**

| 邮箱 | SMTP 服务器 | 端口 | 授权码从哪来 |
| --- | --- | --- | --- |
| QQ 邮箱 | `smtp.qq.com` | 465 | 设置 → 账号 → 开启 IMAP/SMTP → 短信验证 → 生成授权码 |
| QQ 企业邮箱 | `smtp.exmail.qq.com` | 465 | 管理后台 → 客户端专用密码 |
| 163 / 126 | `smtp.163.com` / `smtp.126.com` | 465 | 设置 → POP3/SMTP/IMAP → 开启 → 新增授权密码 |
| Gmail | `smtp.gmail.com` | 465 或 587 | Google 账号 → 安全性 → 两步验证 → 应用专用密码 |
| Outlook / Hotmail | `smtp-mail.outlook.com` | 587 | 账号安全 → 应用密码（需先开双重验证） |
| iCloud | `smtp.mail.me.com` | 587 | Apple ID → 登录与安全 → App 专用密码 |
| 自建 / 其他 | 服务商文档里的地址 | 465 或 587 | 通常用邮箱密码 |

填完点「**发送测试通知**」，收件箱几秒内会收到「BiliNote 测试通知」。没收到先看**垃圾邮件箱**。

### 什么时候会收到通知

- **每轮检查结束时一条**（不逐条轰炸）：一轮里成功/失败/跳过各几个、分别是谁；
- 点「**立即运行一轮**」也会在结束时发一条；
- 一轮里没有需要新总结的视频 → 发一条「（本轮没有需要新总结的视频）」，让你知道它还活着；
- 自动化总开关关着时不发；Windows 计划任务模式（见下文）跑完同样会发。

### 收不到通知怎么排查

| 现象 | 原因与处理 |
| --- | --- |
| 测试通知按钮显示「尚未启用任何通知渠道」 | 只填了内容没**勾选**启用框（或总开关没开） |
| WxPusher 返回 `1001` / 提示超长 | 内容超过平台上限（Markdown 40,000 字 / 转换后 65KB）。一轮视频特别多时先调大「每轮最多新提交」的间隔或减少一次提交量 |
| WxPusher 返回未授权 / code 非 1000 | appToken 或 UID 复制不完整（注意别把空格带进去）；UID 必须是**关注了公众号**的账号才有 |
| WxPusher 测试成功但微信没响 | 微信里搜「WxPusher」公众号 → 确认没被折叠/免打扰；公众号内「我的 → 消息记录」里能看到 |
| 邮件报 `SMTPAuthenticationError` | 用了登录密码而不是授权码；或授权码已过期（重新生成） |
| 邮件报连接超时 / `[SSL: ...]` | 端口填错：465 用 SSL、587 用 STARTTLS，本项目两者都支持，但别把 465 配成 587 |
| 邮件报「Connection unexpectedly closed」 | 公司/学校网络封了 SMTP 端口，换网络或改用 WxPusher |
| 收件箱没有、其他都对 | 先去**垃圾邮件**找；把发件人加白名单 |

### 用命令行单独测一次（可选）

不想开界面、或想接进别的脚本时，可以直接打这个接口（`8483` 是本项目默认后端端口）：

```bash
curl -X POST http://127.0.0.1:8483/api/automation/test_notify
```

返回里每条渠道的 `ok` / `detail` 与设置页「发送测试通知」是同一份诊断信息。

## 双轨调度：应用内 + Windows 计划任务

- **应用运行时**：后端内置调度线程按频率自动执行（推荐日常使用）。
- **应用关闭时**：注册 Windows 计划任务，由 `backend/automation_cli.py` 拉起单轮检查。
  两个入口通过 `config/automation.lock` 文件锁互斥；应用在运行时 CLI 会检测 8483 端口
  自动让位，不会重复执行。

注册（模板见 `scripts/register_watchlater_task.bat`，按注释改三个路径后运行）：

```bat
schtasks /Create /F /TN "BiliNote-WatchLater" ^
  /TR "D:\AIChat\run_watchlater_once.bat" /SC MINUTE /MO 120 /ST 00:05
```

运行器 `run_watchlater_once.bat` 内容（注意 CWD 必须是应用目录）：

```bat
@echo off
cd /d "D:\Program Files\BiliNote"
"<venv>\Scripts\python.exe" "<源码>\backend\automation_cli.py" >> "D:\Program Files\BiliNote\logs\automation_cli.log" 2>&1
```

移除：`schtasks /Delete /TN "BiliNote-WatchLater" /F`

## 手动触发与排查

- 「立即运行一轮」按钮：不等定时，立刻跑一轮（完成后发汇总通知）。
- CLI 日志：`D:\Program Files\BiliNote\logs\automation_cli.log`；
  应用内轮次日志：`D:\Program Files\BiliNote\logs\app.log`（搜「自动化检查轮」）。
- 常见问题：
  - 不执行 → 检查总开关；Cookie 是否有效；`config/automation.json` 是否存在。
  - 收不到通知 → 点「发送测试通知」看每渠道结果（渠道详情直接显示失败原因）。
  - 通知只发一条 → 设计如此：每轮结束发一条汇总（成功/失败清单）。
